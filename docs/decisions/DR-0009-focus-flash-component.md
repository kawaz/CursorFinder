# DR-0009: 第3コンポーネント「フォーカスフラッシュ」— ウィンドウフォーカス変更の視覚エフェクト

## 背景

作者要望 (2026-07-10): ウィンドウフォーカスが切り替わった時に「どのモニタのどのウィンドウへフォーカスが移ったか」を即座に視認できるエフェクトが欲しい。マルチモニタ環境ではフォーカスの行方を見失いやすく、レーザー (カーソル位置) と同種の「いまどこ?」問題。

これを機にアプリのコンポーネント構造を一般化する: 本アプリは「**オーバーレイ描画で『いまどこ?』を可視化するアクセシビリティコンポーネントの集合**」であり、レーザー (カーソル位置)・ワープ (カーソル移動の補助)・フォーカスフラッシュ (キーボードフォーカス位置) はその並列な実装である。

## 決定

1. **コンポーネントとして追加する**: マウスと独立だが「オーバーレイ + 単方向データフロー」という基盤を完全共有するため、別アプリでなく本アプリの第3コンポーネントとする
2. **Action 形式化** (DR-0004 準拠): 入力アダプタが `NSWorkspace.didActivateApplicationNotification` (アプリ切替) + AX observer (`kAXFocusedWindowChangedNotification`、アプリ内のウィンドウ切替) を購読し、`.focusedWindowChanged(appName:windowFrame:displayId:)` action を dispatch する。reducer はフラッシュ状態 (対象矩形 + 開始時刻相当の世代カウンタ) を state に持ち、描画側が減衰アニメーションを描く
3. **座標規約** (DR-0005 準拠): AX のウィンドウフレームは y-up。入力アダプタで即 CG y-down へ変換し、reducer より内側に y-up を持ち込まない
4. **権限**: AX observer はイベントタップと同じアクセシビリティ権限で動く (追加要求なし)。権限なし時はコンポーネントを無効化 (レーザーと同じ degrade 方針)
5. **エフェクトの段階実装**: Phase A = フォーカス先モニタ全体の縁を短時間ハイライト (ウィンドウ枠不要、NSWorkspace 通知のみで実装可能)。Phase B = ウィンドウ枠のアウトライン強調 (AX フレーム取得)。A から出荷し B を重ねる
6. **トグル独立**: メニューでコンポーネント単位に on/off (境界ワープ・プレゼンテーションモードと同じ流儀)

## 却下案

| 案 | 却下理由 |
|---|---|
| 別アプリとして切り出す | オーバーレイウィンドウ管理・権限・store・メニューの全基盤を重複させることになる。「いまどこ?」可視化という目的も同一 |
| ポーリングでフォーカス監視 | NSWorkspace 通知 + AX observer という event-driven の一次手段があるのにポーリングは選ばない |

## 検証の輪郭

- reducer: `.focusedWindowChanged` → フラッシュ state の遷移 (連続切替時は世代カウンタで上書き) の unit test
- AX フレーム y-up → CG y-down 変換の境界テスト (実機トポロジ fixture)
- 実機: アプリ切替 (Cmd-Tab)・同一アプリ内ウィンドウ切替・別モニタへの切替の 3 系で発火確認
